### IMPL-25: The page that answers "what is still open?" must be reachable from inside a screen

**Source:** `docs/impl-guides/operator-findings-20260805-2235-impl-guide-20260805-2242-verify-report-20260806-0042-impl-guide-20260806-0750-verify-report-20260806-1016.md#IV-15`
**Severity/Priority:** ⚠️ medium
**Workstream:** A — the review surface
**Reasoning tier:** standard

#### Context
`comments.html` is linked from `index.html:103` and from nowhere else. The demo panel builds two
content sheets — changelog and product use cases (`proto-sheets.js:2`) — and each carries a
`.pt-sheet-page` link to its full page (`proto-sheets.js:150`). There is no comments sheet, and the
comment layer's own `.proto-comments-tools` toolbar (`proto-comments.js:627`) does not link to the
overview either. A reviewer who is inside a screen, looking at a pin, and wants to know what else is
open has to go back to the hub to find out.

This is the **one red half of BC-3** in the goal document: "linked from `index.html` **and from their
panel sheets**" holds for two of the three pages.

#### What to do
1. Give the panel a comments entry that carries the same `.pt-sheet-page` affordance its two
   siblings do, so the review surface is symmetric and BC-3 is satisfied as written. The sheet's
   body is your call — it has no changelog-like data to list, so it may be a short statement of what
   the page is; what it must carry is the link.
2. Additionally link the overview from the comment layer's own toolbar. That is the surface a
   reviewer is actually looking at when the question arises, and it is the cheaper of the two routes
   for them.
3. If a template twin exists for either file in `design-prototype/templates/`, carry the change
   across; if none exists, say so rather than inventing one.

Follow the pattern in: `proto-sheets.js:145-155`, where the sheet row and its page link are already
built — the link is placed **beside** the sheet rather than inside its redrawn body, which is what
makes it survive every redraw and failure path including `file://`.

#### Scope
- Files: `proto-sheets.js`, `proto-comments.js`
- New files: none
- Dependencies: none

#### Definition of Done
- [ ] On a screen that renders the demo panel, a link whose `href` resolves to `comments.html` is
      reachable from the panel — **counted greater than zero**, not merely "present in the source"
- [ ] The same link is reachable from the comment layer's toolbar on a page where the layer mounts
- [ ] Neither link renders on `comments.html` itself pointing at the page you are already on
- [ ] `index.html`'s three existing links and both existing `.pt-sheet-page` links are unchanged —
      measured, since this card edits the function that builds them
- [ ] The panel still carries no link in export mode (`?nopanel=1`), which is what keeps a pin out
      of a Figma frame
- [ ] `node --check proto-sheets.js proto-comments.js` clean; all four integrity gates pass

#### Edge cases
- `file://`, where `.rp-needs-url` already hides what cannot work: the new link must follow the same
  rule the sheets already follow rather than inventing a second one.
- A page where the comment layer does not mount at all (config absent): the toolbar does not exist,
  so nothing must throw looking for it.
- `comments.html` itself mounts the layer in `overview: true` mode and builds no toolbar — confirm
  the toolbar link's absence there is a consequence of that, not a special case you added.

#### Test scenarios
- **Integration:** headless on `home-c.html`, expand the panel, count links resolving to
  `comments.html`; repeat with `?nopanel=1` and assert zero.
- **Integration:** headless on `listing-c.html` with the layer mounted, read the toolbar's link.

### IMPL-26: A verification nobody can perform must fail loudly, not silently pass

**Source:** `docs/impl-guides/operator-findings-20260805-2235-impl-guide-20260805-2242-verify-report-20260806-0042-impl-guide-20260806-0750-verify-report-20260806-1016.md#IV-20`
**Severity/Priority:** ⚠️ low
**Workstream:** B — the verification contract
**Reasoning tier:** economy

#### Context
`IMPL-12`'s DoD bullet 3 — "the live Firebase path is unchanged: signed in on localhost, the page
still lists every thread" — cannot be evidenced by any automated actor working in this repository.
`comments.rules` admits a reviewer only by a named allowlist entry plus a verified Google email,
`FIREBASE_SERVICE_ACCOUNT` is unset and no key file exists (`tools/comments.js:264`). Iteration 2

required, so the bullet reads like something a careful agent could check.

   what it cannot — a claim about the live backend is in the second set.
3. `README.md` is the file to change. Do not edit `CLAUDE.md`; the orchestrator owns it and has
   already recorded the seam trap there.

Follow the pattern in: `CLAUDE.md`'s comment-layer section, which states the same class of rule for

#### Scope

- [ ] `README.md` names `FIREBASE_SERVICE_ACCOUNT`, says what it is for, and states that a live

### IMPL-27: A criterion phrased over a queried set must assert the set is not empty

**Source:** `docs/impl-guides/operator-findings-20260805-2235-impl-guide-20260805-2242-verify-report-20260806-0042-impl-guide-20260806-0750-verify-report-20260806-1016.md#IV-21`
**Severity/Priority:** ⚠️ medium
**Workstream:** C — the overview's contract

#### Context
`IMPL-11` and `IMPL-12` both carry a DoD bullet measuring a `.cm-thread` selector.
`grep -c "cm-thread"` is **0** in `comments.html` and **0** in `templates/comments.html` — the card
class is `rp-card`. A verifier following the bullet literally runs
`document.querySelectorAll('.cm-thread a')`, gets an empty NodeList, finds that every element in it
satisfies "origin === location.origin", and records a pass.

The bullet passes hardest when the page renders nothing at all. That is the failure mode the whole
loop is supposed to be resistant to, and it survived two rounds inside the guides those rounds were
measured against. The guides are immutable, so the fix is not to edit them — it is to make the next
one impossible to write.

**Reasoning tier:** standard

#### What to do
1. Pin the overview's card class by name in the skill's own suite, so a rename or a drift is caught
   by a test rather than by a reader: assert the populated overview renders a **non-zero** count of
   the class the page actually uses, and that its row links are same-origin. The existing coverage
   asserts the links; it does not assert that any exist.
2. Write the general rule where a DoD author reads it — `SKILL.md`, beside the review-page contract
   that already states the two-link rule. One sentence: a criterion phrased as a universal over a
   queried set must also assert the set is non-empty, because the empty set satisfies every
   universal.
3. Check whether any other assertion in the skill's review-page tests is a universal over a possibly
   empty set, and report what you find.

**Before touching the skill repository, read its `git status`.** A separate round is committing
there and two of this loop's edits are sitting uncommitted in its tree; do not stash, reset, or
check out anything, and report what you found.

Follow the pattern in: `design-prototype/tools/test/review-pages/comments-overview.test.js`, which
already drives the overview through the injected seam — this card adds the missing count assertion
to the same harness rather than building a second one.

#### Scope
- Files: `<skill>/tools/test/review-pages/comments-overview.test.js`, `<skill>/SKILL.md`
- New files: none
- Dependencies: none

#### Definition of Done
- [ ] A new test asserts the populated overview renders **more than zero** cards of the class the
      page actually uses, and that the assertion fails when the count is zero — demonstrated, not
      asserted, by temporarily emptying the store
- [ ] No existing test is deleted, weakened or repointed; the suite total rises from 161
- [ ] `SKILL.md` states the non-empty rule where the review-page contract lives
- [ ] Any other empty-set-satisfiable assertion found in the review-page tests is reported, whether
      or not it is fixed
- [ ] `npm test` in `design-prototype/tools` passes

#### Edge cases
- The suite is a moving target: the parallel round has grown it from 139 to 161 during this loop.
  Read the count before and after your own change and report both, rather than comparing against a
  number written in a guide.
- An assertion that is *correctly* a universal over a possibly empty set — "no card carries the
  trailer" is true and useful on an empty page. The rule is about criteria that are meant to prove
  something rendered, not about every universal.

#### Test scenarios
- **Unit:** the new count assertion, plus the deliberate empty-store run proving it fails.

#### Dependencies
- Blocked by: none
- Blocks: nothing
