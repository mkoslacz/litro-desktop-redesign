litoralulromanesc.ro — desktop redesign

New desktop designs for litoralulromanesc.ro, built on the approved Szallas Group redesign (Redesign sandbox) — the same move as the Hotely.cz re-skin in the sandbox file: identical layout & components, LITRO brand skin, Romanian seaside content. Branding decisions follow the already-refreshed LITRO mobile redesign (navy rating badge, orange stars, red discount pill, navy price, FRIENDS credits).

▶ Selected variant: C. The complete homepage → listing → hotel details → checkout → confirmation flow now uses variant C (workshop), available in Romanian and English through the on-page RO/EN switch. The variant selector has been removed; variants A and B remain archived below for reference. Homepage · D is a workshop alternative: the same C foundation with the offer listing immediately below search.

▶ Interactive prototype, not a mockup. Open any screen and use it: search for a resort, change dates in the calendar, filter results, open the gallery, choose a room, apply promo code LITORAL10, accept the terms, and complete a booking. State carries from one screen to the next.

▶ New: docked search bar. When the main search card leaves the viewport, the same fields collapse into a compact but fully functional bar. Three independent prototype-panel switches control it on the homepage, listing, and hotel page across desktop and mobile. On the hotel page, visitors arriving from our listing use the room-section stay bar; cold arrivals get the compact search bar at the top.

▶ New: pinned campaign card. The first carousel position can stay fixed instead of depending on autoplay. The switch offers Inline and Banner modes. The “Summer super offers” creative is live text rather than a JPG, so it remains editable in Figma and is available in RO and EN.

▶ New: production photos behind a switch. The panel's Photos — Prototype / Production row swaps every image for its real litoralulromanesc.ro counterpart while keeping layout, copy, and prices unchanged. View the full asset pack →, or open the homepage / hotel page directly with production photos.

▶ New: changelog and use cases. The prototype panel links to full review pages for the changelog and use cases. The changelog records what changed between rounds; use cases explain each demo state and open it directly. Ten declared use cases cover all 29 panel options; developer documentation remains in docs/usecases.md. Review data loads from the published or locally served prototype, while file:// shows an explanatory fallback.

▶ New: prototype comments. An approved reviewer signed in with Google can pin the discussed element, start a thread, reply, and resolve it, with live updates for the workshop. A comment preserves the page, language, device, and demo state where it was written. The feature activates after Firebase is configured (see README, Stakeholder comments); until then it stays silent. Before the first commenting round, tell reviewers that their threads, names, and email addresses are stored by the configured Firebase / Google Cloud provider.

Mobile web — the same flow, designed for phones

▶ Mobile web version of flow C at 390 px, matching the “Mobile (REDESIGN)” frames in 🟠 LITRO Master Pages. It combines the team's approved mobile patterns with the desktop prototype's content and commercial logic. Desktop and mobile use the same tokens, same price model, and the same session state.

Mobile-specific behaviour includes full-screen sheets for search, calendar, guests, filters, and sorting; a swipe gallery; a booking bar that rises after the first room is selected; and a fixed checkout bar showing the amount due today. Open the pages in a narrow browser or DevTools device mode.

▶ Desktop ↔ mobile switch. The floating Prototype settings panel moves between corresponding screens while preserving destination and dates. It also controls RO/EN language, guest/member state, listing density, demo inventory, docked search bars, and the pinned campaign card. These are demonstration controls, so they remain in the floating panel rather than the product UI.

Proof, browsing and state — what changed in this round

WhereWhatWhy
Hotel page · galleryTwo-step gallery. Clicking any photo opens a mosaic of every picture first — category chips (rooms / pools / beach / spa / the property / from guests) with counts, tiles in mixed sizes. Clicking one tile switches to the big image with a horizontal thumbnail strip below, arrow keys, a counter and a “‹ All photos” control back to the mosaic. A side rail keeps the score, two guest quotes and the price with a “See the rooms” CTA visible in both steps. On mobile the second step keeps the mosaic — a horizontal strip would waste the lower half of a phone screen, so the chosen photo sits above the same mosaic (selected tile ringed, tap another to swap), and tapping it opens a full-screen zoom: pinch, double-tap for 100 % ↔ 250 %, ± up to 400 %, drag to pan.a strip of thumbnails makes you hunt one photo at a time; a mosaic lets someone scan 16 photos in one glance and pick the one that answers their actual question (how far is the beach? what does the room really look like?). Keeping the score and the price next to the photos means the gallery sells instead of parking the visitor.
Hotel page · reviewsPhotos and clips from guests, under the reviews — a strip of portrait tiles with the uploader’s name, video tiles with a duration badge, a “+42” tile, and reviews that carry their own photos and clips. Everything opens the same gallery, filtered on From guests.the property’s own photos are the marketing version. Guest photos are the only ones a hotel cannot retouch, and they are the most-read part of a hotel page — so they get a named place, not a footnote. They sit under the review cards, because the reviews are what the visitor came to that section for and the pictures read as their continuation.
Hotel page · reviews“Add your own photos and clips” and “Write a review.” Upload flow with a drop zone, a file list you can prune, an optional caption, and an unticked consent that gates the send button. The review form asks for a score out of 10, what you liked, what could be better, and lets you attach files inline without losing what you typed. Both promise moderation within 24 hours; the first published set earns +20 FRIENDS credits.guest content only exists if someone is asked for it. Tying it to the FRIENDS credits that already run the loyalty scheme gives a reason to upload, and the consent stays unticked for the same reason it does at checkout — a pre-ticked box is not consent.
Confirmation · documentsEvery document carries its state: a green circle with a tick for what is ready now (voucher, traveller contract, T&C) and a gray circle with an hourglass, on a dashed row, for what is issued later (deposit invoice, final invoice, room assignment) — with the action reading Download or Coming soon / At check-in, plus a legend.after paying, the open question is “what do I have and what am I still waiting for”. One uniform document icon per row answered neither; the status icon answers both before the row is read.

Handoff — back to Figma & to dev

To Figma — the final file: ⬇ litro-final.fig — one native Figma file with everything: 38 editable frames (layers, texts, photos, exact sizes; single-line texts are auto-width), laid out in labelled rows:
1. Desktop, main RO flow (Home C, Home D, Listing C, Hotel, Checkout, Thank you) · 2. the same six in EN · 3. Desktop states — compact listing cells (B), icon cells (C), signed-in FRIENDS member on listing and home, last rooms, and no results · 4. Desktop archive A / B · 5. Mobile RO (5 screens) · 6. Mobile EN · 7. Mobile states — compact cells (B), horizontal summary (C), signed-in member, low and zero inventory, and hotel with a selected room and booking bar.
Drag it onto the Figma home screen / “Import” — done. Fonts used: Outfit + DM Sans (both in Figma’s Google Fonts catalog). Older exports (litro-desktop-redesign.fig, litro-c-flow-en.fig, litro-mobile-web.fig) are superseded by this one.

How the states are built: screens accept URL parameters — ?auth=in (member), ?density=a|b|c (cell density), ?inv=many|some|few|zero (demo inventory), ?per=10|20|30 (results per page), ?stf= (filter column), ?sthome/stlist/sthotel= (docked bar), ?pin=off|inline|banner, ?assets=prod, ?session=new|site, ?room=2 (preselected mobile rooms), and ?nopanel=1 (export mode without the demo panel). Every file state can therefore be opened as a live link and captured in a frame.

One command rebuilds the file: node tools/refresh.js regenerates the changelog, use-case documentation, hub captures, and litro-final.fig in the correct order. Frames are declared in prototype.json; a new state is one line there, not a hand-edited script. See tools/README.md for details.

Alternative route: the html.to.design plugin (already used by the team for “LITRO Master Pages”) — capture these live pages: home.html, listing.html, hotel.html, checkout.html, thankyou.html from this site’s URL, or via its Chrome extension.

To Figma — mobile: ⬇ litro-mobile-web.fig — a native Figma file with all ten mobile screens as editable frames at 430 px (Romanian on the top row, English below). Same import route as the desktop file: drag it onto the Figma home screen.

To dev — mobile: litro-m.css is the mobile stylesheet (the same token block as litro.css, followed by mobile-only fixed bars, sheets, and single-column cards) and proto-m.js is the mobile interaction engine (the same state key and price model as proto.js, so desktop and mobile stay in sync). The five m-*.html files are reference implementations at 390 px.

To dev: proto.js + proto.css hold all prototype behaviour (state, calendar, filters, gallery, checkout logic) and can be thrown away at implementation time; litro.css is the token sheet (colors, radii, shadows, type as CSS variables — all values in px) and specs.html is the measurement spec (component-by-component). The HTML files themselves are reference implementations — paddings, gaps and font sizes can be lifted 1:1.
Scope note. All 5 templates of the priority flow are covered: listing → hotel details → checkout → thank you, plus homepage. Checkout follows the LITRO mobile redesign model (single page: details + payment, 30% advance option) skinned with the Szallas DS. Photos are placeholders taken from the sandbox assets; swap for real LITRO property photos in production.
